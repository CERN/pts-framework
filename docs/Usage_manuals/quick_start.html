Set up

git clone https://github.com/CERN/pts-framework.git
cd pts-framework
py -3.12 -m venv .venv                    # Python ≥ 3.11
.venv\Scripts\activate                    # every new terminal
pip install -e ".[dev,hardware]"

Editable install: edit and rerun. Linux: python3 -m venv .venv, source .venv/bin/activate. Without activating, python and pypts aren't this venv's.

Run it (venv active)

pypts                              # GUI  (= python -m pypts)
pypts --mode cli
pypts --mode headless --recipe x.yml [--sequence Name]
pypts --log-level TRACE            # every message on every link
python run_recipe_creator.py       # / run_recipe_editor.py

where pypts / which pypts: the venv's copy is first while it's active. Outside it, you get the installed copy (right half).

Done = this passes

pytest tests            # unit_tests/ + functional_tests/ + quality_tests/ (ruff, mypy)
  • The docs describe the code as it now is, updated in the same change.

Architecture

launcher -> spawns  Logger | CORE (Sequencer + Report threads) | HMI (GUI/CLI)
HAL: one driver process per opened device
  • Modules never call each other. Everything goes through CORE; log records go straight to the Logger.
  • HMI↔CORE crosses processes, so its messages must be pickle-safe.
  • New message: dataclass in messages/<a>_<b>_communication.py, add it to the union, add a case in the handler.
  • Handlers: match closed with unhandled(). Don't remove it.
  • Errors: @catch_and_report_errors() in loops, @report_and_reraise() in steps.

Style

  • Plain, readable Python. if/else over clever one-liners.
  • Logging: %-style, never f-strings. INFO+ for the technician, DEBUG for developers.
  • Line length 100. A # noqa: names its rule and gives the reason.

I want to make tests with it

Technician / test author: recipes + test code

Install

uv tool install "<path to the clone>[ssh]"    # or: pipx install, same argument
pypts                                         # any terminal. GUI: File -> Open Recipe
uv tool install --reinstall "<path>[ssh]"     # update after a git pull

Not on a package index yet, so install from a clone. Gives a pypts command on PATH, in its own isolated environment. Extras: [ssh] [ni] [serial] [hardware] (all of them).

1. Test code: plain Python

# board_tests.py
def measure_voltage(channel):
    return {"voltage": 12.1}       # dict: each key judged separately

def greet(name):
    return f"Hello, {name}!"       # scalar: judged as "output"

2. Recipe: YAML

name: Board test
version: 0.1
globals:
  serial_number: ''
report_metadata: [serial_number]   # names the report
---
sequence_name: Main
steps:
  - steptype: PythonModule
    step_name: Measure 12 V rail
    module: board_tests.py         # relative to the recipe
    method_name: measure_voltage
    inputs:
      channel: 1
    outputs:
      voltage: {type: range, min: '11', max: '13'}

4. Run

pypts                                    # GUI, operator at the bench
pypts --mode cli
pypts --mode headless --recipe board.yml # CI, no questions

Headless exit codes: 0 pass, 1 fail, 2 error/stopped, 3 nothing ran.
From code: from pypts.api import Pts, open_gui (see src/pypts/api/showcase.py).
