How to write a device driver

PyPTS hardware layer (pypts.hal) — implements multiple instruments. If a device is missing, you still can add it to a test bench.

If you want to use an AI model to help you writing a driver, give it the context file beside this page: how_to_write_a_driver.md.

1. What a driver is

A driver is one plain Python class for one kind of instrument: a power supply, a multimeter, a remote machine. It knows how to open the connection, do the instrument's verbs, and leave the instrument safe. It imports nothing from the framework except its base class, and it contains no threading, no queues, no process code.

PyPTS runs every device's driver in a process of its own, reached over a pipe. A driver that crashes, hangs or leaks takes its own process down, not PyPTS. You do not write any of that: you write the class below, and the framework does the rest.

2. Two complete examples

Each driver is one Python file of your own, anywhere outside the framework:

~/bench/             
  acme_psu.py
  acme_dmm.py
2.1 A power supply

~/bench/acme_psu.py, reached over TCP (SCPI), standard library only:

"""Driver for the ACME PS-3000 power supply, reached over TCP (SCPI)."""

import logging
import socket

from pypts.hal import PSU, DriverError

# setting up logger in this way would allow the framework to see the traces!
log = logging.getLogger(__name__)

class AcmePsuDriver(PSU):
    """One ACME PS-3000, one TCP connection."""

    def __init__(self):
        self._sock = None                         # the socket for connection

    def connect(self, config):
        host = config["host"]                     
        port = int(config.get("port", "5025"))
        try:
            self._sock = socket.create_connection((host, port), timeout=10)
        except OSError as exc:                    # one clear error, not a bare socket error
            raise DriverError("PS-3000 at %s:%d could not be reached: %s" % (host, port, exc))
        log.info("PS-3000 answered: %s", self._query("*IDN?"))

    def teardown(self):
        if self._sock is None:
            return                                # harmless when nothing is open
        try:
            self._command("OUTP OFF")             # the instrument is left safe first
        finally:
            self._sock.close()
            self._sock = None

    # --- the PSU verbs ---------------------------------------------------

    def set_voltage(self, channel, volts):
        self._command("INST OUT%d" % channel)
        self._command("VOLT %.3f" % volts)

    def set_current_limit(self, channel, amps):
        self._command("INST OUT%d" % channel)
        self._command("CURR %.3f" % amps)

    def output_on(self, channel):
        self._command("INST OUT%d" % channel)
        self._command("OUTP ON")

    def output_off(self, channel):
        self._command("INST OUT%d" % channel)
        self._command("OUTP OFF")

    def measure_voltage(self, channel):
        self._command("INST OUT%d" % channel)
        return float(self._query("MEAS:VOLT?"))

    def measure_current(self, channel):
        self._command("INST OUT%d" % channel)
        return float(self._query("MEAS:CURR?"))

    # --- the wire, private: not an operation ------------------------------

    def _command(self, text):
        self._sock.sendall((text + "\n").encode("ascii"))

    def _query(self, text):
        self._command(text)
        return self._sock.makefile().readline().strip()


# --- standalone check: python acme_psu.py ------------------------------------
# Runs the driver in this process, without PyPTS and without bench.ini. The dict
# stands in for the [psu1] section PyPTS would pass to connect(): values as text.
if __name__ == "__main__":
    logging.basicConfig(level=logging.INFO)
    psu = AcmePsuDriver()
    psu.connect({"host": "192.168.0.40", "port": "5025"})
    try:
        psu.set_voltage(1, 3.3)
        psu.output_on(1)
        print("Channel 1: %.3f V" % psu.measure_voltage(1))
    finally:
        psu.teardown()                              # outputs off, connection closed

Where config comes from? PyPTS passes the device's bench.ini section (step 3) to connect() as a dict of strings. The __main__ block passes the same dict by hand, so you can test the driver without PyPTS.

2.2 A multimeter

~/bench/acme_dmm.py, reached over TCP (SCPI), standard library only:

"""Driver for the ACME DM-100 multimeter, reached over TCP (SCPI)."""

import logging
import socket

from pypts.hal import DMM, DriverError

# setting up logger in this way would allow the framework to see the traces!
log = logging.getLogger(__name__)

# The DMM type's function names, in this instrument's SCPI.
SCPI_FUNCTIONS = {
    "DC_VOLTS": "VOLT:DC",
    "AC_VOLTS": "VOLT:AC",
    "DC_CURRENT": "CURR:DC",
    "AC_CURRENT": "CURR:AC",
    "RESISTANCE": "RES",
}

class AcmeDmmDriver(DMM):
    """One ACME DM-100, one TCP connection."""

    def __init__(self):
        self._sock = None                         # the socket for connection
        self._points = 1
        self._sample_interval_s = 0.001

    def connect(self, config):
        host = config["host"]
        port = int(config.get("port", "5025"))
        try:
            self._sock = socket.create_connection((host, port), timeout=5)
        except OSError as exc:                    # one clear error, not a bare socket error
            raise DriverError("DM-100 at %s:%d could not be reached: %s" % (host, port, exc))
        log.info("DM-100 answered: %s", self._query("*IDN?"))

    def teardown(self):
        if self._sock is None:
            return                                # harmless when nothing is open
        try:
            self._command("*RST")                 # the instrument is left safe first
        finally:
            self._sock.close()
            self._sock = None

    # --- the DMM verbs ---------------------------------------------------

    def configure_waveform_acquisition(self, function, range, sample_rate_hz, points):
        scpi_function = SCPI_FUNCTIONS[function]          # KeyError names a wrong function
        self._command("CONF:%s %g" % (scpi_function, range))
        self._command("SAMP:TIM %g" % (1.0 / sample_rate_hz))
        self._points = points
        self._sample_interval_s = 1.0 / sample_rate_hz

    def read_waveform(self):
        self._command("SAMP:COUN %d" % self._points)
        samples = [float(value) for value in self._query("READ?").split(",")]
        return {"x_origin": 0.0, "x_increment": self._sample_interval_s, "samples": samples}

    def measure_point(self):
        self._command("SAMP:COUN 1")                       # one reading, as configured
        return float(self._query("READ?"))

    def get_frequency(self):
        return float(self._query("MEAS:FREQ?"))

    # --- the wire, private: not an operation ------------------------------

    def _command(self, text):
        self._sock.sendall((text + "\n").encode("ascii"))

    def _query(self, text):
        self._command(text)
        return self._sock.makefile().readline().strip()


# --- standalone check: python acme_dmm.py ------------------------------------
# Runs the driver in this process, without PyPTS and without bench.ini. The dict
# stands in for the [dmm1] section PyPTS would pass to connect(): values as text.
if __name__ == "__main__":
    logging.basicConfig(level=logging.INFO)
    dmm = AcmeDmmDriver()
    dmm.connect({"host": "192.168.0.41", "port": "5025"})
    try:
        dmm.configure_waveform_acquisition("DC_VOLTS", 10.0, 1000.0, 100)
        print("DC voltage: %.4f V" % dmm.measure_point())
        print("100 samples: %s" % dmm.read_waveform()["samples"])
    finally:
        dmm.teardown()                              # instrument reset, connection closed

3. Tell PyPTS about the device

One bare-named section per device in bench.ini, beside config.ini (created empty from a template on first start):

Linux / macOSWindows
~/.config/pypts/bench.ini%LOCALAPPDATA%\pypts\bench.ini

From the PyPTS GUI: File → Open Config opens config.ini in the system's text editor, and hovering the menu entry shows its full path. bench.ini is in the same folder. The menu opens only config.ini, not bench.ini.

driver names your file and, after a colon, the class in it:

Linux / macOSWindows
[psu1]
driver = ~/bench/acme_psu.py:AcmePsuDriver
host = 192.168.0.40
port = 5025

[dmm1]
driver = ~/bench/acme_dmm.py:AcmeDmmDriver
host = 192.168.0.41
port = 5025
 
[psu1]
driver = C:\bench\acme_psu.py:AcmePsuDriver
host = 192.168.0.40
port = 5025

[dmm1]
driver = C:\bench\acme_dmm.py:AcmeDmmDriver
host = 192.168.0.41
port = 5025
  • The file path may be absolute, start with ~, or be relative to the folder bench.ini is in (driver = drivers/acme_psu.py:AcmePsuDriver).
  • Nothing has to be installed or exported: PyPTS loads the file itself.
  • driver is read by the framework; every other key goes to your connect(config) as text — convert numbers yourself.
  • Edits to the config are applied to the application after restarting.

Test code then reaches the device by its logical name. Save that as dmm_tests.py beside a recipe, which calls it like any Python step:

from pypts.hal import get_device

def power_up():
    psu = get_device("psu1")        # opened on first use, closed when the run ends
    psu.set_voltage(1, 3.3)
    psu.output_on(1)
    return {"vout": psu.measure_voltage(1)}


def supply_rail():
    dmm = get_device("dmm1")
    dmm.configure_waveform_acquisition("DC_VOLTS", 10.0, 1000.0, 1)
    return {"v_rail": dmm.measure_point()}

And call it in the recipe

name: DMM check
description: Reads the 3.3 V rail.
version: 0.1
---
sequence_name: Main
description: One measurement.
steps:
  - steptype: PythonModule
    step_name: 3V3 rail
    description: Within 5 %.
    module: dmm_tests.py
    method_name: supply_rail
    outputs:
      v_rail: {type: range, min: '3.135', max: '3.465'}

4. Several files? Use a package

A driver split over several modules lives in a package of your own (any name except pypts), named in bench.ini by its dotted path, driver = bench_drivers.acme_psu.AcmePsuDriver:

~/bench/
  bench_drivers/
    __init__.py       (empty)
    acme_psu.py
    scpi_helpers.py

Python must then be able to import it. Set this in the terminal you start PyPTS from — each device's process inherits it:

Linux / macOSWindows (PowerShell)
export PYTHONPATH=~/bench
 
$env:PYTHONPATH = "C:\bench"

To make it permanent, add the line to ~/.bashrc on Linux or run setx PYTHONPATH C:\bench on Windows.

5. The rules

5.1 Derive from a device type, never from BaseDriver

Import the type from pypts.hal: PSU, DMM, Scope, Load, SSH, or Other for anything else. A driver that derives from BaseDriver directly is refused at open.

Why: every power supply should be driven the same way. The type fixes the method names every driver of that kind must have, so psu.set_voltage(1, 3.3) works regardless. Swap the instrument by changing driver = in bench.ini; the test code and recipes stay as they are. A driver that leaves out a verb of its type cannot be opened.

The verbs each type requires:

TypeVerbs
PSUset_voltage, set_current_limit, output_on, output_off, measure_voltage, measure_current (channel counts from 1)
DMMconfigure_waveform_acquisition(function, range, sample_rate_hz, points) — function DC_VOLTS, AC_VOLTS, DC_CURRENT, AC_CURRENT or RESISTANCE; read_waveform(); measure_point() — one reading, however the meter is configured; get_frequency()
Scopeconfigure_waveform_acquisition(channel, volts_per_division, seconds_per_division, points); read_waveform(channel); measure_point(channel) (channel counts from 1)
Loadset_mode (CC/CV/CR/CP), set_level, input_on, input_off, measure_voltage, measure_current
SSHexecute, put_file, get_file
Othernone — every public method you add is the interface

A type's verbs are abstract and mandatory — a driver that omits one fails at open with a TypeError naming it.

5.2 Implement the lifecycle

  • connect(config) — open the connection the section describes. All values are text. Raise when the instrument cannot be reached: the device then fails at open with your message.
  • teardown() — where the instrument is left safe: outputs and loads off, then disconnect. There is no separate safe-state method. Teardown runs at every end of a device — a normal close, PyPTS dying, or on a fresh connection when your driver was stuck — so it must work right after connect() on an instrument in any state, and be harmless when nothing is open. The framework runs it exactly once per connection, never twice.
  • recover(config) — optional. The default is teardown + connect; override it when the instrument has a cheaper reset. Test code triggers it with recover_device(device) (from pypts.hal); the framework never recovers on its own.

5.3 Logging and printing

Log with logging.getLogger(__name__). Your driver's records keep their level in the PyPTS run log, prefixed Device 'psu1': ... — INFO and above reaches the technician's panel, so log at INFO what an operator should see and keep the chatter at DEBUG. Of course, use WARNING and ERROR levels as you see fit.

5.4 Vendor libraries

Import the vendor library at the top of the module, and turn a missing one into a message that names what to install:

try:
    import pyvisa
except ImportError as exc:
    raise ImportError(
        "AcmeScopeDriver needs pyvisa; install it with 'pip install pyvisa'."
    ) from exc

The shipped pypts.hal.drivers.ssh.SshDriver shows the pattern; pypts.hal.drivers.weather.OpenMeteoDriver is a driver that needs no vendor library at all and turns every failure of its far end into one clear error.

5.5 Do not start processes

The driver process is a daemon, and a daemon cannot have children: do not use multiprocessing inside a driver. Threads are allowed, but anything they log between calls is delivered with the next call, not immediately.

6. What the framework does for you

SituationWhat happens
Driver raisesTest code gets DriverError("Device 'psu1': 'set_voltage' failed: ...") with your message; the device stays usable; the traceback is in the log at DEBUG.
A call takes longer than 30 sThe stuck driver process is killed and the call raises. The instrument keeps its state until the device is closed — then a fresh process connects and runs teardown() (the rescue) — or until test code calls recover_device(device).
The driver process crashesDriverError("Device 'psu1' stopped unexpectedly (exit code N)."); recover_device(device) brings it back on a fresh process.
The run ends, in any wayEvery opened device is closed, newest first: teardown() on the live process, or on a fresh connection when the process was stuck or gone. A device that still cannot be torn down is an ERROR naming it (... may still be energised).
PyPTS diesThe pipe closes and the driver process runs teardown() itself before exiting — unless it is stuck in a call.
The run is abandoned (Stop gave up on its thread)Every opened device is torn down on one 16 s shared deadline, newest first, and then cannot be opened or recovered again.
bench.ini was discarded at startupEvery get_device() fails with the discarded-bench DriverError until the file is fixed and PyPTS restarted.
The one net you provide: everything above funnels into your teardown(). If it does not reliably switch the outputs off, nothing else will.

7. Testing the driver

  • In-process, vendor library mocked — build the class directly and call its methods; see tests/unit_tests/test_hal_ssh.py.
  • Through a real driver process — build ConnectionDriver("x", "my_module.MyDriver", {...}), open it with its _open() and call it; see tests/unit_tests/test_hal_connection.py and the loopback driver it uses.
  • On the bench, outside PyPTS — a plain script can use the same devices. The INI file given to from_ini() uses bench.ini's format: one bare-named section per device, e.g. [psu1]. 
    from pypts.hal import LocalSetup, get_device

if __name__ == "__main__":                 # required: spawn re-imports this file
    with LocalSetup.from_ini("bench.ini"):
        print(get_device("psu1").measure_voltage(1))
    Without the __main__ guard every driver process re-runs the script and dies at once with stopped unexpectedly (exit code 1).

8. Checklist

  • ☐ Derives from PSU / DMM / Scope / Load / SSH / Other, not BaseDriver.
  • ☐ connect(config) treats every value as text and raises a clear error when the instrument is unreachable.
  • ☐ teardown() leaves the instrument safe, works right after connect(), and is harmless when nothing is open.
  • ☐ The wire protocol is in _private helpers.
  • ☐ Arguments and return values are picklable.
  • ☐ Logs through logging.getLogger(__name__); operator-relevant lines at INFO.
  • ☐ Vendor import at the top of the module, with the extra to install named.
  • ☐ No multiprocessing inside the driver.
  • ☐ driver = names the file and class (~/bench/acme_psu.py:AcmePsuDriver), or a package importable on the bench.
  • ☐ A [<name>] section exists in bench.ini and the demo recipe or a standalone script talks to the instrument.
