PyPTS Recipe Format — the simplified rules

The new engine's recipe contract, as enforced by src/pypts/recipe/rules.py and validator.py. The legacy engine's rules are the separate page recipe_rules.html.
One idea: a recipe states only what it needs. Every optional field left out is assumed empty — no {} or [] boilerplate is ever required. An optional key written with no value (a bare locals: line) counts as absent too.
Case does not matter in the recipe's own language: keys (NAME:, Step_Name:), steptype values, mapping type values, and the main_sequence lookup all ignore case. What names your code or data keeps its case, because Python and file systems care: module, method_name, variable names, mapping entry names (they become keyword arguments and output keys) and every compared value.

The file

A recipe is one multi-document YAML file. Document order matters: document 1 is the header, every document after it is a sequence. There must be at least one sequence.

Header (document 1)

FieldRuleWhen absent
namerequired—
descriptionoptional""
versionoptional""
format_versionoptional assumed written for the current format; a mismatch is logged as an ERROR and the recipe still loads (hard refusal comes ~v1.0)
main_sequenceoptional the first sequence in the file
globalsoptional{}

Unknown header keys (e.g. the legacy recipe_version, continue_on_error) are tolerated and ignored, so old files still load.

Sequence (every following document)

FieldRuleWhen absent
sequence_namerequired — (must also be unique in the file)
stepsrequired — (must contain at least one step)
descriptionoptional""
setup_stepsoptional [] — setup steps are ordinary steps that run first
teardown_stepsoptional [] — teardown always runs, even after a failure or an abort
parameters, locals, outputs optional{}

Steps

Every step needs steptype and step_name; description is always optional. The steptype value is case-insensitive and names one of the ported types — note the names carry no Step suffix. Two of them run; Indexed is expanded into ordinary steps while the recipe loads:

steptype: PythonModule — call one Python function

FieldRuleMeaning
modulerequired a file beside the recipe (example_tests.py / example_tests) or a dotted import name
method_namerequired the function to call
input_mappingoptional keyword arguments; absent = the function takes none
output_mappingoptional how to judge/store what came back; absent = nothing to judge, verdict DONE

steptype: Wait — sleep

FieldRuleMeaning
wait_timerequired seconds, written directly on the step — no input_mapping nesting, and no output_mapping: a fixed wait has nothing to resolve and nothing to judge

steptype: Indexed — the same step, once per parameter set

Not a step that runs: it is expanded when the recipe loads into one ordinary step per parameter set, each with its own id, its own row in the step table and its own row in the report. Ten sets means ten steps — nothing loops at run time.

FieldRuleMeaning
templaterequired an ordinary step mapping — the type and everything the cases share. It needs no step_name: each generated step is named after its own parameters
parameter_setsrequired a non-empty list; one entry becomes one step
inputs (in a set)optional argument name → value. Direct values, merged over the template's input_mapping
expect (in a set)optional output name → expected value, i.e. an equals check. A set must carry at least one of inputs/expect
- steptype: Indexed
  step_name: Add numbers
  description: Additions, each checked against its own expected sum.
  template:
    steptype: PythonModule
    module: example_tests.py
    method_name: add
  parameter_sets:
    - inputs: {a: 1, b: 1}
      expect: {sum: 2}
    - inputs: {a: 2, b: 3}
      expect: {sum: 5}

Produces the steps Add numbers [a=1, b=1] and Add numbers [a=2, b=3]. A set that varies only its expectation has no parameters to show and is named Add numbers 1/2 instead.

inputs/expect are deliberately terse — a set is a test case and reads like a row of a table. A case needing range, passfail, local or global puts it on the template, which takes the full vocabulary; set entries are merged over it key by key. An Indexed step carries no input_mapping, output_mapping or id of its own — all three are refused, because they would apply to nothing or to N steps at once. skip: true on it skips every generated step.

The smallest valid recipe

name: Wait demo
---
sequence_name: Main
steps:
  - steptype: Wait
    step_name: Only wait
    wait_time: '0.5'

A fuller example — four function calls and a wait, showing input_mapping/output_mapping in use — is resources/recipes/python_demo.yml.

Validation

validator.py checks every mandatory field against rules.py before anything is built, and the parser raises one RecipeError naming every problem at once — a bad file is fixed in one round trip. Loading a recipe (Recipe.from_file(path)) is the verification: if it returns, the file is well-formed and fully built in memory; if not, the one error says everything that is wrong.

Where the rules live: change a rule in src/pypts/recipe/rules.py and the validator, the parser and this page must follow — this page is documentation, the code is the authority.
