HAL server: design on one page

Revision 4, 2026-11-05. The full design is in docs/superpowers/specs/2026-11-04-hal-server-design.md (41 decisions). This page is a draft, not yet approved and not yet re-reviewed.

Picture

What and why

  • The HAL moves out of CORE into its own package, src/pyhal/, which never imports pypts (the same pattern as pyrade_xy_graph). It later becomes a subrepository.
  • It runs as a standalone local service that PyPTS, scripts and later other languages connect to.
  • One process owns the bench, so every device call visibly goes to one place.
  • Unchanged: the drivers, the device types, today's per-device teardown sequence (with its rescue), the per-device processes, and the DriverError texts. Only import paths change (from pyhal import PSU).

Connect or start

  1. PyPTS (in CORE) or a script calls pyhal.connect(bench=...).
  2. If a HAL is listening on the fixed port, the client uses it. If its bench file differs, it logs a warning naming both. If devices are still open, it warns and reuses them.
  3. If nothing is listening, it starts python -m pyhal --bench FILE detached (it survives its starter), waits up to 15 s, connects, and remembers that it started it.
  4. If that fails, PyPTS starts anyway, and get_device() reports the reason.

Lifetime

EventWhat happens
Start press endsCORE (on RunFinished) fences old device handles and sends close_all off its event loop. The next Start waits until it's done. Teardown results go to the run log.
PyPTS closes normallyclose_all, then shutdown only if this PyPTS started the HAL; otherwise the HAL stays up. If a test is stuck, closing first waits for the stuck call, at most 30 s.
PyPTS crashesThe HAL does nothing: devices stay as they are (a PSU may stay on), and it waits for the next client. This is a conscious change from today.
HAL stopped (shutdown, Ctrl+C)It always tears every open device down first.
HAL diesDevice calls fail through the normal step-error path, and View → HAL shows it lost. Restart PyPTS to get devices back. There's no automatic restart.

Protocol

  • JSON, one object per line, a kind field. hello comes first. One request at a time, no ids. Heartbeats can arrive in between.
  • Requests: open, call, recover, info, close, close_all, shutdown. The HAL knows devices, not runs.
  • Plain Python sending: send("call", device="psu1", operation="output_off").
  • Errors carry an origin: driver, hal or protocol. NaN, infinity and bytes go in tagged form. Limit 16 MB per message. No version for now.
→ {"kind":"call","device":"psu1","operation":"measure_voltage","args":[1],"kwargs":{}}
← {"kind":"heartbeat","pid":4120,"busy":{...},"devices":{...}}
← {"kind":"result","value":12.03}

In PyPTS

  • CORE owns everything HAL: connect, heartbeat watch, snapshot, the device slot, close_all, shutdown. The Sequencer has no HAL code; only the steps call devices.
  • The HAL heartbeat is watched but is non-fatal: if it's lost, the HAL is marked lost, and the session goes on.
  • View → HAL: a plain read-only window showing the HAL's pid, bench file and status, what it's busy with, and each device's state and last error. It's built from the latest heartbeat and has a Refresh button.
  • bench.ini stays beside config.ini. PyPTS passes its path, and the HAL reads it. The HAL keeps its own log file because it outlives PyPTS.

What you're accepting

  • If PyPTS crashes, instruments may stay energised.
  • One request at a time: test-code threads take turns, even on different devices.
  • Teardown runs after RunFinished, so its results aren't in that run's report.
  • Closing PyPTS with a stuck test can take about 30 s longer.
  • Large waveforms travel as JSON, about 700–800k samples within 16 MB.
