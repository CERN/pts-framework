HAL server, phase 3 — PyPTS uses the HAL server: Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: PyPTS reaches its devices through the standalone HAL server instead of in-process, and the in-process path (LocalSetup) is removed.

Architecture: A new core/hal_link.py in CORE connects to the HAL (or starts it, with or without its monitor window, per [hal] show_window) on a worker thread at startup, re-logs the HAL's log lines as HAL: ..., and runs the close on both of CORE's closes. The Sequencer wraps each run in with pyhal.run_scope(): where LocalSetup is today. Test code keeps calling pyhal.get_device(). No new HMI↔CORE messages: View → HAL is phase 4.

Tech Stack: Python ≥ 3.11, standard library sockets (phase 2's pyhal.client), PySide6 for the monitor, pytest + pytest-qt.

Spec: docs/superpowers/specs/2026-11-04-hal-server-design.md (rev 5): §6.1-6.4, §9, §10, §12. Phase 2's plan (2026-11-23-hal-phase2-server.md) for what exists already.

Decisions already taken (2026-11-23)

#Decision
P1New key [hal] show_window, bool, **default true**, in the Settings dialog.
P2Every schema key is mandatory, so the new key **raises CONFIG_VERSION to 5.0.0** (old config.ini files are discarded with the version notice until updated or recreated).
P3show_window = true: when PyPTS has to start a HAL, it starts the monitor in serve mode, which starts the HAL. PyPTS still counts as its starter (the start nonce goes through the monitor), so PyPTS's close sends shutdown; the window then closes itself (--exit-with-hal).
P4show_window matters only when PyPTS starts the HAL. A HAL found running is used as it is; no window is opened for it.
P5Tests run during phase 3 (user allowed it for this work).

Global Constraints

  • pyhal never imports pypts (tests/quality_tests/test_pyhal_independence.py).
  • import pyhal stays light (no socket, no PySide6): test_import_pyhal_stays_light.
  • Logging %-style; INFO and above for the technician, developer detail at DEBUG (logger/logging_rules.md; check its fixed lifecycle phrases before adding INFO lines).
  • match/case closed with unhandled() wherever a message union is matched.
  • A thread entry point never calls init_logging().
  • The close is on the closing thread itself, never handed to a worker (spec §6.4 step 4).
  • CORE_SHUTDOWN_TIMEOUT_S and the BENCH_MAY_BE_ENERGISED text stay as they are (§6.4).
  • Documentation moves with the code in the same task (CLAUDE.md); no git commit steps (the user commits).
  • Code style: plain, if/else over conditional expressions, line length 100, ruff + mypy clean.

Review Focus

  1. PyPTS closed within seconds of starting, while the HAL is still starting (up to HAL_START_TIMEOUT_S = 15 s): the close must not block CORE's event loop past the HMI's 15 s heartbeat limit. → Task 4 test test_close_during_the_startup_connect_does_not_block.
  2. A run started before the startup connect finished (headless runs start at once): the run's first get_device() waits for the connect and then works. → Task 1 test test_run_scope_waits_for_a_pending_connect, Task 5 test.
  3. The HAL is not reachable at all (start failed, port taken by something else): PyPTS starts, the run's get_device() fails with the reason, the step is an ERROR, the run finishes. → Task 4 test_a_failed_connect_is_what_get_device_reports.
  4. The test suite never touches the real HAL port or the real bench, including engines started in spawned processes. → Task 4 PYPTS_HAL switch, set in tests/conftest.py; Task 7 full-suite run checks no pyhal process is left (Get-CimInstance check).
  5. The window start where the HAL inside it cannot start (bad bench): PyPTS gives up after HAL_START_TIMEOUT_S with the startup file's tail; the window stays open showing the failure. → Task 2 test test_connect_with_window_reports_a_failed_start.

def test_run_scope_waits_for_a_pending_connect(start_hal):
    hal = start_hal()            # the existing threaded-server fixture of this file
    client.connect_pending()
    connected = threading.Event()
    def late_connect():
        time.sleep(0.5)
        client.connect_only(hal.port, scope=False)
        connected.set()
    threading.Thread(target=late_connect).start()
    with client.run_scope():
        assert connected.is_set()
        device = client.get_device("loop1")
        assert device.echo("x") == "x"

def test_note_unavailable_is_what_get_device_raises():
    client.note_unavailable("bench.ini was discarded at startup, so this start has no devices: bad")
    with client.run_scope():
        with pytest.raises(DriverError, match="bench.ini was discarded at startup"):
            client.get_device("loop1")

def test_run_scope_without_a_pending_connect_does_not_wait():
    started = time.monotonic()
    with client.run_scope():
        pass
    assert time.monotonic() - started < 0.5

      • __init__(self, log_level: int, *, show_window: bool, port: int = DEFAULT_PORT) -> None

      • _sink(self, level: int, message: str) -> None — log.log(level, "HAL: %s", message).
    • Log lines (CORE's logger pypts.core.hal_link): INFO Started the HAL server. / Connected to the HAL server. (found running) / WARNING The HAL server could not be reached: <reason> ; pid, port, bench path, window at DEBUG.
