XY graph + stream container — design

2026-10-19 · branch architecture_refactor · status: agreed design, not implemented

1. Goal

A PythonModule step's test function produces live data (a demo sine wave), registers it under a name in a stream container, and the GUI draws it live in an XY graph while any step whose recipe says graph: <name> runs. The stream container is not part of the HAL (revised 2026-10-19, §3). The XY graph code is copied from C:/git/pyrade_xy_graph (GitLab pyrade/hmi/gui/pyrade_xy_graph) for now and becomes a package / sub-repository later.

2a. Architecture pictures

3. Stream container — src/pypts/stream_handler/ (fills the stub)

Why not the HAL: the HAL is about devices and is meant to ship on its own; streams need no device (the sine demo is simulated) and a driver runs in its own process, so it could never call the container directly anyway. Keeping the container free of every other pypts import means it can ship on its own too.

from pypts.stream_handler import register_stream

stream = register_stream("sine", unit="V")
stream.push(t, y)          # one sample, or two equal-length arrays
stream.close()
  • No imports from the rest of pypts. A StreamSession(folder, on_open=None) is the per-run container; on_open(name, csv_path, unit) is a plain callback.
  • One active session per process, the same pattern as the active LocalSetup (hal/local_setup.py). The Sequencer opens one for each run next to its existing with LocalSetup(...) in execute_sequence(), giving it the run folder (RunStarted.run_dir, made by start_run_folder()) and an on_open that builds StreamOpened and sends it.
  • In a plain script, with StreamSession("some/folder"): activates one, as LocalSetup.from_ini() does for devices.
  • register_stream(name, unit=None) opens (append mode) <folder>/streams/<name>.csv, writes the header x,y if the file is new, and calls on_open.
  • Stream.push(x, y) appends rows and flushes; guarded by a lock so a background thread may push.
  • Stream.close() closes the file; idempotent. At run end the container closes every stream still open.
  • With no active session, register_stream raises a clear error (as get_device does).
  • Public API in stream_handler/__init__.py: register_stream, Stream, StreamSession.

4. Connection layer — one message

@dataclass
class StreamOpened:
    name: str
    csv_path: str      # absolute: the HMI is another process
    unit: str | None = None
  • Declared in messages/run_events.py, added to the Sequencer→CORE union and the CORE→HMI union.
  • Built and sent by the Sequencer's on_open callback (the container never sees the message class), on the same outgoing path as Runtime.emit; CORE relays it unchanged, like StepStarted/StepFinished (core.py, the progress-event case).
  • hmi_client.py gets a presentation hook; the GUI implements it, the CLI does nothing.
  • Pickle-safe: only strings.

5. Recipe key

- steptype: PythonModule
  step_name: Sine sweep
  module: sine_tests.py
  action_type: method
  method_name: run_sine
  graph: sine
  • graph: str | None = None on _StepFields in recipe/recipe_schema.py (and STEP_COMMON_DEFAULTS), stored as step.graph by Step.__init__.
  • Carried to the frontend on StepSummary.graph (messages/run_events.py), so the GUI knows at recipe load which rows want a graph.
  • Indexed: the wrapper's value goes on every generated step unless the template names its own (same rule as image_path).

6. GUI

  • A new small widget in hmi/gui/ (e.g. stream_graph.py) wraps pyrade_xy_graph.ui.plot_widget.ScopePlotWidget + pyrade_xy_graph.core.data_store.DataStore, and a pure, Qt-free CSV tail reader (reads from a byte offset, returns only complete new lines).
  • The GUI keeps stream name → csv_path for the current run, filled by StreamOpened, cleared at run start.
  • On StepStarted for a row with graph: X: the right column swaps the picture for the graph, clears it, and a QTimer (a few times a second) reads X.csv from the start and then new lines. If X is not registered yet, the graph waits empty and attaches when StreamOpened(X) arrives.
  • The graph stays after the step ends; the next StepStarted decides the right column again (picture, logo or its own graph). Run end returns to the existing idle behaviour.
  • On StepFinished of a step with graph: X when X was never registered in this run: one WARNING, e.g. Step 'Watch it' shows graph 'bg_sine', but no stream of that name was registered. (wording to be checked against logger/logging_rules.md).

7. Copied code — src/pyrade_xy_graph/

  • Verbatim copy of pyrade_xy_graph/ (core/, ui/, main.py, __init__.py); no tests/, no old_graph/.
  • Added to packaging ([tool.setuptools.packages.find]), excluded from ruff and mypy.
  • New dependency: pyqtgraph. The plot path needs only that and numpy; h5py/nptdms/pandas are used only by parts PyPTS does not call — they are not added.
  • Later swap: delete the folder, add the package or sub-repository; no PyPTS code changes.
