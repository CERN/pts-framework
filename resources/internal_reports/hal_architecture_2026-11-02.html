PyPTS HAL — architecture

How src/pypts/hal/ is structured: layers, process model, call path, lifetime and failure handling. Written from the source and hal/hal.md as of 2026-11-02 (branch architecture_refactor).

Logical namesTest code asks for get_device("ssh1"); the bench file maps names to drivers.
One process per deviceEach driver runs in its own spawned process; a crash or hang stays there.
Run-scopedDevices open lazily within one run and are torn down, newest first, before RunFinished.
One teardown pathThe teardown ladder is the only place a device ends: live → fresh process → reported.

1. Process and component view

The HAL sits outside the PyPTS message layer: driver processes are reached over their own multiprocessing Pipes, never via CORE's queues. Driver log records travel back over the Pipe and are re-logged in CORE as Device 'x': ….

2. Layers (top to bottom)

Public API — __init__.py: get_device, LocalSetup, ConnectionDriver, BaseDriver, DriverError, six device types.
Run scope — local_setup.py: LocalSetup (devices of one run), the process-wide active slot, abandon_active_setup(), bench section readers, split_section().
Device proxy + ladder — connection_driver.py (parent side): ConnectionDriver, Pipe protocol, timeouts, teardown ladder, rescue.
Driver host — connection_driver.py (child side): driver_process_main(), load_driver_class(), answer(), log/print forwarders.
Contracts — base_driver.py (connect, teardown, recover), device_types.py (PSU, DMM, Scope, SSH, Load, Other: verb sets).
Drivers — drivers/: LoopbackDriver, SshDriver (reference), OpenMeteoDriver (showcase).

About 1,670 lines in total; connection_driver.py (718) carries most of the complexity. local_setup.py imports config_handler lazily so a driver process, which imports pypts.hal too, never loads configuration.

3. Key design decisions

DecisionWhy
Process per device (spawn, daemon)Isolation: a crashing, hanging or leaking vendor library cannot take PyPTS down. Spawn passes sys.path, so source-tree runs work.
Logical names in bench.iniTest code is bench-independent; the same functions run standalone via LocalSetup.from_ini().
Typed device bases, not a free ABCA driver must pick PSU/DMM/…; the verb set is a contract. A driver of no type is refused.
Dynamic proxy via __getattr__Operations come from the driver's hello; unknown names fail locally with no round trip.
No separate safe-state methodteardown() is the safe state and must work on a fresh connection to an instrument in any state.
One active-setup slot per processNot thread-local: threads test code starts belong to the run.
Driver stability is the driver's jobThe framework tries the ladder once and reports; it does not retry forever.
One interpreterEvery driver runs on PyPTS's Python; the per-device python key is refused.

4. How a call travels

① Resolve

get_device("ssh1") → active LocalSetup reads the cached bench sections once, split_section() pulls driver and call_timeout_s (default 60 s); everything else is text for connect().

② Open

open() starts process Device ssh1; it imports and builds the driver and sends hello (type, operations) or fatal, within STARTUP_TIMEOUT_S (30 s). Then connect(settings). Any failure, even an interrupt, kills the process.

③ Call

device.execute("uname -r") → (method, args, kwargs) pickled whole over the Pipe → result or error; log / printed may arrive first. A lock serialises calls per device.

Pipe protocol

MessageDirectionNote
(method, args, kwargs)PyPTS → driverUnpicklable args refused before sending
("hello", device_type, operations)driver → PyPTSOnce, first
("fatal", reason)driver → PyPTSInstead of hello
("log", level, logger_name, message)driver → PyPTSAny time; read only while a call waits
("printed", line)driver → PyPTSstdout/stderr forwarded, DEBUG
("result", value) / ("error", type, msg, tb)driver → PyPTSDevice stays usable after an error

5. Lifetime and the teardown ladder

Lifetime

  • Per run (one Start press): Sequencer.execute_sequence() wraps the step layer in with LocalSetup(...). Devices open on first use and close newest first after teardown steps, before RunFinished, whatever the result. GUI, CLI, headless and pypts.api.Pts all share this path.
  • Standalone: with LocalSetup.from_ini("bench.ini"): in a script (must sit under if __name__ == "__main__": because of spawn).
  • PyPTS dies: the Pipe closes and the driver process runs teardown() itself, unless a teardown already ran or a call is stuck.
  • Abandoned run (Stop gave up on the thread): abandon_active_setup() empties the slot, refuses further opens and runs the ladder for every device on one shared deadline of 16 s (ABANDONED_DEVICES_TIMEOUT_S = 5 + 10 + 1). Unsafe devices are named in one CRITICAL. Abandonment is final.

Ladder (close() / abandon())

1 · Live teardownteardown() on the running process (abandon: within 5 s, ABANDON_TEARDOWN_TIMEOUT_S).
→
2 · RescueKill; a fresh process connects and tears down, within RESCUE_TIMEOUT_S (10 s).
→
3 · ReportERROR: "could not be torn down and may still be energised". No further retries.

Recovery is explicit

A call that exceeds call_timeout_s only kills the process and raises; nothing rescues mid-run. Test code calls device.recover(): driver's own recover() → else full teardown and a fresh process with connect() → else DriverError.

6. Failure model

Every failure surfaces to test code as one type, DriverError; uncaught, the step ends in ERROR through the normal step path.

EventEffect
Driver raisesDriverError; device usable; traceback at DEBUG
Pickling fails either wayDriverError; device usable
Call timeoutProcess killed; instrument keeps state until the ladder
Process dies"stopped unexpectedly (exit code N)"
Import / build / connect fails"could not be opened"; process killed
Config errorUnknown name, no driver key, bad call_timeout_s, python key, discarded bench file

7. Extension points

Writing a driver

from pypts.hal import PSU

class MyPsu(PSU):
    def connect(self, config): ...   # all values are text
    def teardown(self): ...          # outputs off, then disconnect
    def set_voltage(self, channel, volts): ...
  • Every public method becomes an operation; reserved names (RESERVED_NAMES: name, open, close, recover, abandon, …) are refused at open.
  • Vendor library imported at module top with an ImportError naming the extra ([ssh], [ni], [serial], [hardware]).
  • No child processes from a driver (it is a daemon).
  • Declared in bench.ini: [name], driver = dotted.Class.

8. Known gaps and architectural risks

  • Stop does not interrupt a call blocked inside a driver; only call_timeout_s bounds it.
  • No bulk-data side channel: waveforms are pickled through the Pipe.
  • Driver logs between calls queue in the Pipe; once the buffer fills, logging threads in the driver block until the next call.
  • A rescue reconnects with the same settings: instruments refusing a second connection, or a connect() slower than 10 s, cannot be rescued.
  • PyPTS killed outright runs no ladder; the driver's own end-of-Pipe teardown is the only net.
  • No automatic recovery policy; only device.recover() from test code.
  • No PSU, DMM, Scope or Load driver ships yet — only their device-type bases.
  • Single interpreter: vendor libraries needing another Python (e.g. 32-bit DLLs) are unsupported.
