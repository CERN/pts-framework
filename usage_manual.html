1. What PyPTS does

PyPTS runs a recipe against hardware. A recipe is a YAML file that lists sequences, and each sequence lists steps, for example calling a Python function, waiting, or asking the operator a question. Every step ends with a verdict (PASS, FAIL, DONE, SKIP, ERROR or STOP). Every run leaves a report and a run log.

The usual workflow is: open a recipe → pick a sequence → start → answer questions → read the result.

2. Starting it

From the repository root:

python -m pypts              # GUI (the default)
python -m pypts --mode cli   # text shell instead of a window

On Windows you can also double-click run_pypts.bat, or run it from a shell with the same options, e.g. run_pypts.bat --mode cli. It uses the repository's .venv when there is one.

To try it out, load the smallest demo recipe: resources/recipes/Development_recipes/wait_recipe.yml (two short waits).

5. GUI mode

Running a recipe

  1. Open (toolbar, or File → Open Recipe) and pick a .yml file. The step table fills in, and the window title shows the recipe name.
  2. Pick a sequence in the drop-down. The recipe's main sequence is selected by default.
  3. Start. Each row goes Pending → Running... → verdict. The small green bar at the right of the line above the table shows how far the run is, e.g. 6 / 15 (40 %). It counts every step, including the steps inside groups and skipped ones, but not the group rows themselves. It keeps its final value when the run ends, and starts again from 0 on the next run.
  4. When a step asks something, answer it in the right-hand panel (see below).
  5. The left side has two tabs. Run shows the step table. Results shows PASS/FAIL counts and a result tree. Each step opens into its Inputs and Outputs, e.g. voltage = 12.1 with its check (range 11 .. 13). It fills in as each step finishes, so you can look during a run.
  6. When the run ends, the Results tab pulses blue until you click it. The window doesn't switch tabs for you. Starting a run clears the results and goes back to Run, and so do opening a recipe and picking a sequence (those two keep the last results).

Groups in the step table. A row with a small triangle (▸) is a Sequence step: a group of steps from another sequence of the recipe. Groups start folded. Click the group's name (or double-click the row) to unfold it and see its steps, indented under it; click again to fold it. Right-click the table for Expand all / Collapse all. A folded group still gets its result during a run, and so do the steps inside it; nothing unfolds by itself.

When a run ends, the label above the step table shows a summary, e.g. Done - demo: FAIL / 5 steps: 3 PASS, 1 FAIL, 1 SKIP, or Stopped - demo if you stopped it. The status bar at the bottom just names the state: Idle, Running, Pausing, Paused, Finished or Stopped.

Hover over any button to see what it does, or why it's greyed out. Hover over a step's result to see why it failed (if it did) and the values it measured. Between runs, click a step's name or description to see the whole sequence that step belongs to, exactly as it is written in the recipe file, with the clicked step highlighted and scrolled into view. For a step inside a called sequence, that is the called sequence. Clicking a group's description shows the sequence it calls, whole (clicking its name folds or unfolds it). The row goes pale blue while the panel is up. Move the mouse onto the panel to scroll it with the wheel; moving the mouse anywhere else closes it.

Answering questions

A step can ask one of three things:

  • A choice: click one of the buttons (or use the arrow keys and Enter).
  • Text, such as a serial number: type it and press OK.
  • A file or folder: type a path or use Browse.... OK only becomes active when the path exists.

Cancel is always there. Cancelling makes that step ERROR, and the sequence continues with the next step.

6. CLI mode

Start with python -m pypts --mode cli, then type commands at the pypts> prompt:

CommandDoes
load_recipe <path>Loads a recipe and lists its sequences. The main one is marked (main).
start_sequence <name>Runs that sequence. Results print as steps finish.
stop_sequenceAborts the current run.
statusShows the current status.
helpLists the commands.
exit (or quit, stop)Leaves PyPTS. Ctrl+C does the same.
pypts> load_recipe resources/recipes/Development_recipes/wait_recipe.yml
Recipe loaded: Wait demo (version 0.2)
Sequences: Main (main)
pypts> start_sequence Main
...
pypts> exit
Careful: the CLI can't answer questions yet. Any step that asks the operator something (a choice, text, or a path) is declined and ends as ERROR. Use the GUI or the API for recipes that ask questions. Also, stop exits the program. To abort a run, type stop_sequence.

Without Qt

CLI mode doesn't need PySide6, so it works on a bench with no display.

7. From Python code (API)

Use pypts.api to run recipes from your own script. Always put the code under if __name__ == "__main__":, because PyPTS starts extra processes that re-import your file.

from pypts.api import Pts, open_gui

def answer(request):
    # Called for every question. Return an option / text / path, or None to decline.
    return request.options[0]

if __name__ == "__main__":
    # No window:
    with Pts() as pts:
        pts.load_recipe("bench.yml")
        result = pts.run(answer=answer)       # blocks until the run ends
        print(result.result)

    # Or the normal window, with the recipe already loaded and started:
    open_gui("bench.yml", start=True)

More cases (progress printing, stopping from another thread, and more) are in api_showcase.py at the repository root, for example python api_showcase.py headless.

8. Headless / CI mode

Runs one recipe with nobody at the keyboard, then exits. There's no window and no prompt.

python -m pypts --mode headless --recipe bench.yml
python -m pypts --mode headless --recipe bench.yml --sequence Calibration

It prints each step as it finishes (with its inputs and outputs), the final result and the report folder. Then it exits with a code you can check:

Exit codeMeaning
0Passed (PASS or DONE)
1A step failed (FAIL)
2Not judged: the run ended in ERROR or STOP, skipped everything, or was interrupted with Ctrl+C
3Nothing ran: bad arguments, the recipe is missing or refused, the sequence doesn't exist, or the engine failed
Questions are declined. Any step that asks the operator something ends as ERROR, so the exit code is 2. Recipes meant for CI shouldn't ask questions. If yours must, answer them from code with the API.

Example in a pipeline:

python -m pypts --mode headless --recipe tests/board.yml
if [ $? -ne 0 ]; then echo "board test did not pass"; exit 1; fi

9. Where files go

WhatWindowsLinux
Settings (config.ini)%LOCALAPPDATA%\pypts\config.ini ~/.config/pypts/config.ini
Reports and logs%LOCALAPPDATA%\pypts\reports ~/.local/share/pypts/reports

These are the defaults. You can change the reports folder in Edit → Settings or in config.ini; the logs go with it.

  • Report: each run gets one folder, <timestamp>_<recipe>, containing report.csv (written step by step), report.html and the run's own log, pypts_<timestamp>.log, with every line of that run.
  • Session log: one file in the reports folder each time PyPTS starts, and a new one each time you unload the recipe. It holds everything outside the runs and names each run's log. Its first lines give the version, the user and the machine, which makes it useful to attach to a bug report. After an unload, the end of the old file names the new one, and the top of the new one names the old one.
  • config.ini: created on the first start. If it's broken or from an incompatible version (a different major number in config_version), PyPTS tells you, uses the defaults for that run, and leaves the file untouched. Fix the file, or delete it to have it recreated. Saving in Edit → Settings changes only that setting's line; your comments and anything you added by hand stay where they are.

10. Hardware devices

Test code reaches a device by a logical name; config.ini says what that name is. Each device runs its driver in a process of its own, opened the first time a run asks for it and closed when the run ends.

[hardware.ssh1]
driver = pypts.hal.drivers.ssh.SshDriver
host = 192.168.0.10
username = tester
key_filename = C:\Users\tester\.ssh\id_ed25519
from pypts.hal import get_device

def read_kernel():
    result = get_device("ssh1").execute("uname -r")
    return {"kernel": result["stdout"].strip()}
  • Install the driver's library: pip install pts-framework[ssh] (also [ni], [serial], or [hardware] for all).
  • Optional key: call_timeout_s (longest one call may take, default 60). Every driver runs on PyPTS's own Python; a python key from an older version is refused when the device opens, so remove it.
  • Edits and defaults: device sections are read from the configuration PyPTS loaded at start, so a hand edit of config.ini applies from the next start. Restore default settings recreates config.ini and removes the [hardware.*] sections too: copy them first.
  • SSH: an unknown host key is refused; add the host to your known_hosts, name a file with known_hosts =, or set accept_unknown_host = true. A password key works, but the file is plain text: prefer key_filename. Keys named like a password are masked in the log lines PyPTS writes about configuration and device connections.
  • No hardware? driver = pypts.hal.drivers.loopback.LoopbackDriver answers with whatever it is sent; resources/recipes/Development_recipes/hal_demo.yml uses it.
  • Outside PyPTS: with LocalSetup.from_ini("bench.ini"): (from pypts.hal) makes get_device() work in a script of your own. Put that code under if __name__ == "__main__":: each device's process starts by re-reading your script.
  • Headless and API runs get the same devices.

11. Helper tools

ToolStart withFor
Recipe Creator run_recipe_creator.bat or
python run_recipe_creator.py		 Writing and editing recipes in a window, with live validation. If the YAML text can't be shown as a tree (it doesn't parse, or has the wrong shape), the tree and the validation pane are grayed out, the text stays as you typed it, and the log says why. Fix it in the editor, press Undo, or press Undo to Last Valid. Save still writes the text as it is. A broken file opens the same way.

12. Troubleshooting

You seeDo
"GUI mode needs PySide6…"Install PySide6, or start with --mode cli.
"pypts configuration discarded"Your config.ini is broken or outdated. The run continues on defaults. Fix the file, or delete it.
A recipe won't loadThe error names the problem. Open the recipe in the Recipe Creator to see every issue at once.
A step that asks a question ends ERROR in the CLIThat's expected, see §6. Use the GUI or the API.
Anything elseRerun with --log-level TRACE and attach the run log.
