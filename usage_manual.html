1. What PyPTS does

PyPTS runs a recipe against hardware. A recipe is a YAML file that lists sequences, and each sequence lists steps, for example calling a Python function, waiting, or asking the operator a question. Every step ends with a verdict (PASS, FAIL, DONE, SKIP, ERROR or STOP). Every run leaves a report and a run log.

The usual workflow is: open a recipe → pick a sequence → start → answer questions → read the result.

2. Starting it

From the repository root:

python -m pypts              # GUI (the default)
python -m pypts --mode cli   # text shell instead of a window

On Windows you can also double-click run_pypts.bat, or run it from a shell with the same options, e.g. run_pypts.bat --mode cli. It uses the repository's .venv when there is one.

During the refactor the Debug Monitor window opens next to every run. It's a developer tool, so add --no-debug-monitor if you don't want it.

To try it out, load the smallest demo recipe: resources/recipes/Development_recipes/wait_recipe.yml (two short waits).

5. GUI mode

Running a recipe

  1. Open (toolbar, or File → Open Recipe) and pick a .yml file. The step table fills in, and the window title shows the recipe name.
  2. Pick a sequence in the drop-down. The recipe's main sequence is selected by default.
  3. Start. Each row goes Pending → Running... → verdict.
  4. When a step asks something, answer it in the right-hand panel (see below).
  5. When the run ends, the Results tab shows PASS/FAIL counts and a result tree. Each step opens into its Inputs and Outputs, e.g. voltage = 12.1 with its check (range 11 .. 13).

The toolbar

ButtonDoes
OpenLoads a recipe. Greyed out during a run.
StartRuns the selected sequence.
Pause / ResumeHolds the run. While paused you can click the tabs to look around.
StopAborts the run. Steps that didn't run end as STOP.
Report (far right)Opens this run's report folder, or the reports folder if there hasn't been a run yet.

Hover over any button to see what it does, or why it's greyed out. Hover over a step's result to see why it failed (if it did) and the values it measured. Hover over a step row for about 1 second between runs to see that step's YAML.

Answering questions

A step can ask one of three things:

  • A choice: click one of the buttons (or use the arrow keys and Enter).
  • Text, such as a serial number: type it and press OK.
  • A file or folder: type a path or use Browse.... OK only becomes active when the path exists.

Cancel is always there. Cancelling makes that step ERROR, and the sequence continues with the next step.

6. CLI mode

Start with python -m pypts --mode cli, then type commands at the pypts> prompt:

CommandDoes
load_recipe <path>Loads a recipe and lists its sequences. The main one is marked (main).
start_sequence <name>Runs that sequence. Results print as steps finish.
stop_sequenceAborts the current run.
statusShows the current status.
helpLists the commands.
exit (or quit, stop)Leaves PyPTS. Ctrl+C does the same.
pypts> load_recipe resources/recipes/Development_recipes/wait_recipe.yml
Recipe loaded: Wait demo (version 0.2)
Sequences: Main (main)
pypts> start_sequence Main
...
pypts> exit
Careful: the CLI can't answer questions yet. Any step that asks the operator something (a choice, text, or a path) is declined and ends as ERROR. Use the GUI or the API for recipes that ask questions. Also, stop exits the program. To abort a run, type stop_sequence.

Without Qt

CLI mode doesn't need PySide6, so it works on a bench with no display. Add --no-debug-monitor there too.

7. From Python code (API)

Use pypts.api to run recipes from your own script. Always put the code under if __name__ == "__main__":, because PyPTS starts extra processes that re-import your file.

from pypts.api import Pts, open_gui

def answer(request):
    # Called for every question. Return an option / text / path, or None to decline.
    return request.options[0]

if __name__ == "__main__":
    # No window:
    with Pts() as pts:
        pts.load_recipe("bench.yml")
        result = pts.run(answer=answer)       # blocks until the run ends
        print(result.result)

    # Or the normal window, with the recipe already loaded and started:
    open_gui("bench.yml", start=True)

More cases (progress printing, stopping from another thread, and more) are in api_showcase.py at the repository root, for example python api_showcase.py headless.

8. Headless / CI mode

Runs one recipe with nobody at the keyboard, then exits. There's no window and no prompt.

python -m pypts --mode headless --recipe bench.yml
python -m pypts --mode headless --recipe bench.yml --sequence Calibration

It prints each step as it finishes (with its inputs and outputs), the final result and the report folder. Then it exits with a code you can check:

Exit codeMeaning
0Passed (PASS or DONE)
1A step failed (FAIL)
2Not judged: the run ended in ERROR or STOP, skipped everything, or was interrupted with Ctrl+C
3Nothing ran: bad arguments, the recipe is missing or refused, the sequence doesn't exist, or the engine failed
Questions are declined. Any step that asks the operator something ends as ERROR, so the exit code is 2. Recipes meant for CI shouldn't ask questions. If yours must, answer them from code with the API.

Example in a pipeline:

python -m pypts --mode headless --recipe tests/board.yml
if [ $? -ne 0 ]; then echo "board test did not pass"; exit 1; fi

9. Where files go

WhatWindowsLinux
Settings (config.ini)%LOCALAPPDATA%\pypts\config.ini ~/.config/pypts/config.ini
Run logs%LOCALAPPDATA%\pypts\logs ~/.local/share/pypts/logs
Reports%LOCALAPPDATA%\pypts\reports ~/.local/share/pypts/reports

These are the defaults. You can change the log and report folders in Edit → Settings or in config.ini.

  • Report: each run gets one folder, <timestamp>_<recipe>, containing report.csv (written step by step) and report.html.
  • Run log: one file per run. Its first lines give the version, the user and the machine, which makes it useful to attach to a bug report.
  • config.ini: created on the first start. If it's broken or from an older version, PyPTS tells you, uses the defaults for that run, and leaves the file untouched. Fix the file, or delete it to have it recreated.

11. Troubleshooting

You seeDo
"GUI mode needs PySide6…"Install PySide6, or start with --mode cli.
"pypts configuration discarded"Your config.ini is broken or outdated. The run continues on defaults. Fix the file, or delete it.
A recipe won't loadThe error names the problem. Open the recipe in the Recipe Creator to see every issue at once.
A step that asks a question ends ERROR in the CLIThat's expected, see §6. Use the GUI or the API.
Debug Monitor is emptyStart with --log-level DEBUG.
Anything elseRerun with --log-level DEBUG and attach the run log.
